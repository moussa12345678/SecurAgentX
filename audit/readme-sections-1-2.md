## What is SecurAgentX?

SecurAgentX is a **true autonomous AI agent framework for security research** — not a script-chain wrapper with an LLM bolted on top. At its core sits **VulnAgent**, a reasoning-driven agent that **decides** what to do next, **selects** from 25+ built-in tools, **pivots** when a strategy stalls, and **writes new tools on the fly** when nothing in its arsenal fits the target. Every action the agent proposes flows through a **Governance Layer** that classifies each command as SAFE, PRIVILEGED, or DESTRUCTIVE before execution, so genuine autonomy never comes at the cost of operational control. A cross-session memory subsystem (ChromaDB vector store + JSON-backed skill store) lets the agent remember which payloads worked against which WAFs, which subdomain patterns a target's CDN tends to expose, and which exploit chains succeeded on similar stacks — across sessions, across targets, across operators. The result is a framework that thinks like a junior penetration tester who never forgets, not a glorified `nmap | grep` pipeline.

```text
User: "Find vulnerabilities in example.com"
    │
    ▼
┌──────────────────────────────────────────────────────────────┐
│  VulnAgent — True AI Agent (free will, 25+ tools)            │
│  ├── Reasons about target and builds strategy                │
│  ├── Selects tools from AVAILABLE_TOOLS (freedom to skip)    │
│  ├── Creates new tools on the fly (edit_own_tool)            │
│  ├── Learns from cross-session memory (ChromaDB + Skills)    │
│  └── Pivots freely — no locked phases or forced ordering     │
└──────────────────────────────────────────────────────────────┘
    │
    ▼
┌──────────────────────────────────────────────────────────────┐
│  Governance Layer                                            │
│  ├── SAFE         → Execute immediately                      │
│  ├── PRIVILEGED   → Ask user approval                        │
│  └── DESTRUCTIVE  → Block with popup (Allow / Always / Deny) │
└──────────────────────────────────────────────────────────────┘
    │
    ▼
Reports: findings, CVSS scores, AI analysis  →  ~/.securagentx/reports/
```

Unlike "script chaining with an AI on top", SecurAgentX gives the AI **genuine autonomy** — it decides what to do, in what order, and how to adapt when a path fails.

## Features

### True AI Agent Architecture

SecurAgentX is built around **VulnAgent** — a genuine autonomous AI agent with **free will** over tool selection and execution flow. The agent runs a continuous `[REASON] → [TOOL SELECT] → [EXECUTE] → [ADAPT]` cycle: it thinks about the target, picks the next move, runs it, observes the result, and reasons again — never locked into a fixed phase order.

```text
┌──────────────────────────────────────────────────────────────┐
│                    AI REASONING CYCLE                         │
│                                                              │
│   [REASON] ──► [TOOL SELECT] ──► [EXECUTE] ──► [ADAPT]      │
│      │                                          │            │
│      └──────────────────────────────────────────┘            │
│                    (continuous loop)                          │
└──────────────────────────────────────────────────────────────┘
```

What makes VulnAgent a *true* agent — not a script chain with an AI painted on top:

- **No script chains** — the AI decides every step. There is no locked phase ordering, no `recon → scan → exploit` conveyor belt; if the agent finds a foothold during recon it pivots straight to exploitation, and if an exploit fails it loops back to enumeration without a human re-dispatching the workflow. The legacy `pipeline/phase_registry`, `pipeline/unified`, and `core/brain.py` script-driven pipeline has been **fully removed** — SecurAgentX now runs on a pure AI agent architecture.
- **25+ built-in tools** — from port scanning and subdomain enumeration to fuzzing, BOLA testing, WAF detection, JWT/SSTI/SSRF/XXE probing, PoC generation, and report writing. Every tool ships an AI-consumable description so the agent understands when and why to invoke it. Tools are described in the registry (`tools/tool_registry.py`) and surfaced to the agent via `AVAILABLE_TOOLS`.
- **`edit_own_tool`** — the agent can create and modify its own tools at runtime. When it discovers that a stock scanner misses a parameter or needs a custom payload, it patches the tool in place and reuses the modified version for the rest of the engagement (and persists the change as a Skill for future targets).
- **`create_tool`** — the agent can author arbitrary Python tools on the fly. If nothing in the existing arsenal fits (a niche GraphQL endpoint, a proprietary protocol, a custom auth scheme), it writes a new one, saves it to the skill store, and reuses it on future targets — extending its own capability surface without a code deploy.
- **Cross-session Memory** — powered by ChromaDB (vector + FTS5 full-text search) plus a JSON-backed skill store. The agent remembers which payloads worked against which WAFs, which subdomain patterns a target's CDN tends to expose, and which exploit chains succeeded on similar stacks — across sessions, across targets, across operators. Memory operations: `memorize()`, `recall()`, `forget()`, `save_skill()`, `recall_skill()`, `list_skills()`.
- **MCP Auto-start** — the Model Context Protocol server boots in the background on **every** CLI invocation, exposing all 25+ dynamic tools to any MCP-aware client over both stdio (for Claude Desktop and similar) and HTTP (port 8080, for REST consumers). No manual MCP lifecycle management required — `start_mcp_if_enabled()` is invoked from `main()` on every boot.

### Memory & Skills

SecurAgentX maintains two complementary persistent stores that turn one-off findings into a cumulative knowledge base:

| Store | Format | What it does |
|:-----:|:------:|--------------|
| **Memory** | `~/.securagentx/data/memory.json` | Saves findings, strategies, target patterns, and outcomes across sessions — the agent's episodic + semantic recall (backed by ChromaDB with FTS5). |
| **Skills** | `~/.securagentx/data/skills.json` | Stores reusable tool scripts, exploits, and techniques authored by `create_tool` / `edit_own_tool` — the agent's procedural toolkit. |

The agent can `memorize()`, `recall()`, `forget()`, `save_skill()`, `recall_skill()`, and `list_skills()` — building up a personal knowledge base over time that survives process restarts and is shared across targets. Skills authored on one engagement are immediately available on the next, so the agent gets measurably better the more you use it.

### Safety by Design — Governance Layer

Every command the agent proposes passes through a **Governance Layer** before execution. The layer classifies each action by risk level and enforces the appropriate confirmation policy:

| Risk Level | Action | Example |
|:----------:|--------|---------|
| **SAFE** | Execute immediately | `nmap`, `curl`, `python3`, passive recon |
| **PRIVILEGED** | Ask user approval | `sudo apt install`, `pip install` |
| **DESTRUCTIVE** | Show popup (Allow / Allow Always / Deny) | `rm -rf /`, `dd`, `mkfs` |

The governance layer is **policy-driven** (defined in `securagentx/governance.py`), not hard-coded per command, so operators can extend SAFE / PRIVILEGED / DESTRUCTIVE classifications and add new gating predicates (e.g. `passive_only`, `in_scope`) without touching the agent itself. The `--mode` flag (`strict` / `ask` / `auto`) controls how aggressively the agent self-approves PRIVILEGED actions during autonomous runs.

### MCP Integration

Full support for the **Model Context Protocol** — the MCP server auto-starts in the background on every CLI invocation, exposing all 25+ dynamic tools to any MCP-aware client (Claude Desktop, custom integrations, REST consumers).

```text
securagentx scan example.com
    │
    ▼
main() ──► show_banner() ──► start_mcp_if_enabled() ──► MCPServer (2 transports)
                                                                │
                                                     ┌──────────┴──────────┐
                                                     ▼                     ▼
                                              stdio (Claude Desktop)   HTTP (port 8080)
                                              25+ dynamic tools        REST API
```

Configure MCP servers via the Textual TUI (`Ctrl+,` → MCP Servers) or by editing `mcp.json` directly. The default MCP servers shipped with SecurAgentX — auto-copied from `mcp.json.example` on first run — are:

- **`sequential-thinking`** — structured problem-solving (linear step-by-step reasoning via `npx -y @modelcontextprotocol/server-sequential-thinking`)
- **`chain-of-recursive-thoughts`** — deep recursive analysis (thoughts that critique and extend prior thoughts)
- **`mcp-structured-thinking`** — step-by-step planning with explicit state transitions
- **`memory`** — cross-session memory backed by the official MCP memory server (`npx -y @modelcontextprotocol/server-memory`)

User config (`~/.securagentx/mcp.json`) overrides project config; the auto-start is wrapped in a try/except so a misconfigured MCP server can never block CLI startup.

## Quick Start

### Prerequisites

- **Python 3.10+** — tested on 3.10, 3.11, 3.12, 3.13, and 3.14 (see `pyproject.toml` classifiers).
- **Node.js + npm** — only required for the default MCP servers (`sequential-thinking`, `memory`, etc.), which are auto-started via `npx -y`. The core CLI and VulnAgent work without Node, but MCP integrations will skip silently.
- An **AI provider API key** — OpenAI, Anthropic, Google Gemini, Groq, DeepSeek, or local Ollama. Additional providers (Cohere, Hugging Face, Replicate, Bedrock, Kimi, GLM, Qwen) are also wired in `securagentx/providers/`.

### Install

**End users** (from a built wheel / PyPI-style install). SecurAgentX is licensed under **GPL-3.0** — see [LICENSE](https://github.com/moussa12345678/SecurAgentX/blob/main/LICENSE):

```bash
pip install securagentx
```

**Contributors and local development** (editable install from a clone of the repo):

```bash
git clone https://github.com/moussa12345678/SecurAgentX.git
cd SecurAgentX
pip install -e .

# Optional: pull in dev tooling (pytest, black, isort, flake8, mypy, ruff)
pip install -e ".[dev]"
```

> **Dependencies note:** `pip install` pulls in ~25 runtime dependencies declared in `pyproject.toml` — `rich` + `textual` + `questionary` + `prompt_toolkit` for the TUI/CLI; `openai`, `anthropic`, `google-generativeai`, `cohere`, `huggingface-hub`, `replicate` for LLM providers; `chromadb` + `sentence-transformers` for vector memory; `tiktoken` for token counting; `networkx` for the local knowledge graph; `aiosqlite` + `nest-asyncio` + `tenacity` for async; `trafilatura` + `googlesearch-python` + `duckduckgo-search` for web intelligence; and `python-telegram-bot` for the optional notification bridge. The first install may take a few minutes because of the `sentence-transformers` and `chromadb` wheels. MCP server binaries are **not** pip-installed — they are fetched on demand via `npx`, so make sure `node`/`npx` are on your `PATH` before the first `securagentx` run. API keys go in a `.env` file at the repo root (see `.env.example`); never commit keys to git.

### First Run

```bash
# 1. System health check — verifies Python deps, config dir, MCP prerequisites, and provider keys
securagentx doctor

# 2. Configure AI providers (interactive setup wizard — writes ~/.securagentx/config.json and .env)
securagentx configure

# 3. Launch the Textual TUI for chat-style interaction
securagentx tui
```

`securagentx doctor` will tell you exactly which optional prerequisites are missing (e.g. `npx` not found, no API key set, ChromaDB index not yet initialized) so you never have to guess what's broken. The first run also auto-copies `mcp.json.example` → `~/.securagentx/mcp.json` so the default MCP servers are available immediately.

### Basic Usage Examples

```bash
# Autonomous AI vulnerability hunt — VulnAgent reasons, selects tools, and pivots freely
securagentx hunt example.com

# AI-driven scan (equivalent entry point to `hunt` — same VulnAgent engine, same 25+ tools)
securagentx scan example.com

# Smart reconnaissance — subdomain discovery, IP resolution, service fingerprinting, asset correlation
securagentx recon example.com

# Full autonomous vulnerability hunting (long-form alias for `hunt`)
securagentx vuln-hunt example.com

# Multi-target hunt — comma-separated list, the agent treats each as an in-scope asset
securagentx hunt "example.com, api.example.com, staging.example.com"
```

All `scan` / `hunt` / `vuln-hunt` commands route through the **same VulnAgent engine** — the same true AI agent with 25+ tools, memory, and free will. There are no script chains, no forced phases, no hidden phase ordering. The legacy shortcuts `bb` (BOLA), `check` (recon), and `test` (WAF) are deprecated and silently redirect to VulnAgent for backward compatibility.
